# 비공개 방 제한 초대 입장 수정

## 확인한 코드 문제

- 회의실 상단 `초대 링크`가 비공개 방에서도 `/lobby/{roomId}`만 복사했습니다. 이 주소에는 초대 토큰이 없으므로 신규 사용자는 일반 입장 API에서 거부됩니다. 기존 호스트 관리의 제한 초대 발급 기능은 별도로 존재했습니다.
- 초대 주소는 로그인 리다이렉트의 `state.from`에 유지되지만 회원가입 완료 후 `/login`으로 이동할 때 전달하지 않았습니다.
- 대시보드 입장 칸은 숫자만 받았으므로 전체 제한 초대 링크를 붙여넣으면 입장할 수 없었습니다.
- 빈 `?invite=`는 일반 입장으로 처리됐고, 서버의 초대 거부 안내는 여러 원인을 하나의 문구로 표시했습니다.

사용자의 로컬 DB/실제 실패 요청에 직접 접근하지 않았으므로 위 문제 중 어느 경로가 이번 신고의 원인인지는 확정하지 않았습니다. 유효한 토큰을 보낸 요청 자체가 500 등으로 실패하는 경우에는 서버 로그 확인이 필요합니다.

## 수정

- 상단 초대 팝업에서 HOST가 유효 시간/최대 인원을 지정해 실제 제한 초대를 발급합니다. 비공개·팀 방에는 토큰 없는 주소 복사 버튼을 표시하지 않습니다. HOST가 아닌 참가자는 호스트에게 초대를 요청하도록 안내합니다.
- 로그인/회원가입 전환 링크와 회원가입 완료 리다이렉트에서 원래 초대 주소를 유지합니다. 인증 후 복귀 경로는 내부 `/lobby/{id}` 또는 `/room/{id}`로 한정합니다.
- 대시보드가 회의실 번호와 전체 초대 링크를 모두 받습니다. URL을 붙여넣으면 roomId/token만 추출해 현재 앱의 로비로 이동합니다. 입력한 외부 주소로 요청을 보내지는 않습니다.
- 로비는 토큰이 있으면 `/room/{id}/controls/redeem`만 호출합니다. 빈 값/중복/잘못된 형식의 토큰을 일반 join으로 전환하지 않습니다. 입장 성공 후 토큰 없는 회의실 주소로 replace 이동합니다.
- 초대의 만료, 폐기, 횟수 소진, 잘못된 방/토큰, 잠긴 방을 구별해 안내합니다. 기존 호스트/멤버 권한, 방 잠금, 내보내기, 사용 횟수 제한을 완화하지 않습니다.
- 예기치 않은 서버 오류는 BE 로그에 메서드/경로와 예외를 기록합니다. 요청 본문·쿼리 문자열·Authorization은 따로 기록하지 않습니다.

## DB

이번 변경은 DB 구조 변경이 없어 새 `erd_patch_v2`나 실행 SQL을 만들지 않았습니다. 이전 `erd_patch_v1`의 `room_bans`와 `action_items.revision`은 여전히 필요합니다. v1 미적용 상태에서 오류가 난다면 이전 패치 안내를 먼저 확인하세요. 로컬 DB에는 접속하거나 SQL을 실행하지 않았습니다.

## 적용 및 재현

1. FE/BE 각각 main을 pull하고 재시작합니다.
2. 비공개 방 HOST로 `초대 링크 → 제한 초대 링크 발급 → 제한 초대 링크 복사`를 사용합니다. 토큰 없는 기존 주소는 신규 참가자용 제한 초대가 아닙니다.
3. 다른 계정/시크릿 창에서 링크를 열고 로그인하거나 회원가입한 뒤 `회의실 입장`을 누릅니다. 기본 최대 인원은 1명이므로 여러 신규 참가자에게 같은 링크를 보낼 때는 발급 인원을 늘리거나 각각 발급합니다.
4. 개발자 도구에서 `POST /api/room/{id}/controls/redeem`이 전송되는지 확인합니다. 기존 멤버의 재입장은 초대 사용 횟수를 늘리지 않습니다.
5. 잠긴 방은 호스트가 잠금을 해제해야 신규 참가자가 들어올 수 있습니다. 만료/소진/폐기된 초대는 새로 발급합니다.
6. 계속 실패하면 해당 요청의 HTTP 상태, 응답 `message`, 같은 시점 BE 오류 로그를 확인합니다. 공유하는 로그나 캡처에서는 초대 토큰/Authorization/쿠키를 가립니다.

## 검증

- FE `npm test -- --maxWorkers=1`: 기존 테스트와 토큰 보존/잘못된 링크/리다이렉트/제한 입장 API 테스트.
- FE `npm run build`: TypeScript/Vite 빌드.
- `tests/invite-browser-check.mjs`: 1440/390/360px, 로그인→비공개 입장, 회원가입→로그인 페이지 새로고침→입장, 전체 링크 붙여넣기, 기존 멤버 재입장, 토큰 없음/빈 토큰/만료/소진/폐기/잠금 차단. 결과는 `tests/evidence/invite-browser-results.json`.
- BE `roomContractTest`: 비공개 방의 유효한 초대 수락, 다른 방 토큰 거부, 거부 사유 구분 등.
- 브라우저 REST/STOMP는 모킹입니다. 실제 사용자 PostgreSQL에 연결한 종단 검증은 수행하지 않았습니다.
